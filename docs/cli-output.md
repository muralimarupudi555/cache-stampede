# Captured output

Generated by `tools/capture_cli.py`, which runs the real command against a real load against a real thread pool and records what came back. Regenerated by `make bench`; only the timings and the exact counts move between runs.

## A plain TTL cache on one hot key

```console
$ cache-stampede --cache naive --duration-seconds 3
naive, ttl 0.5s, origin 50ms, 200 requests/s, 1 key

reading                               measured   derived
--------------------------------------------------------
origin calls per refresh                  11.0        11
worst refresh observed                      38
peak simultaneous origin calls              38
origin calls in total                       82
--------------------------------------------------------
hit rate                               86.33%    90.00%
requests made to wait                  13.67%
p99 response                            50.3 ms

when the key expired, 11 requests reached the origin at once and it peaked at 38 simultaneous calls.
The hit rate for the same run was 86.33%. Nothing on a cache dashboard distinguishes this from a cache that is working.

the harness ran out of workers (38 in flight against a pool of 38), which caps the stampede at the pool size and makes this a measurement of the harness
$ echo $?
5
```

## A scenario that cannot show a stampede

```console
$ cache-stampede --origin-seconds 0
invalid scenario: origin_seconds must be positive. An origin that answers instantly has no window for anyone else to miss in, which is the absence of the effect rather than a measurement of it.
$ echo $?
2
```
